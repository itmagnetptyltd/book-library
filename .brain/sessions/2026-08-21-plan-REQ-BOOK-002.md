# Plan — REQ-BOOK-002@v1

**Each Book card shows that Book's Book ID, Name, Author, Language and Price.**

`agreed`, version 1, **9 acceptance criteria**, no open ambiguities. Its one
dependency, REQ-BOOK-001, is `in_progress` and green — the Gallery and the card
exist, so nothing here is invented.

Planned 2026-08-21.

## Why this requirement

`/feature-plan` was invoked with no ids. Three requirements are unbuilt:
REQ-BOOK-002, REQ-BOOK-013 and REQ-BOOK-014. This one is chosen because it is
the only one of the three that needs code rather than evidence, and because it
is the single fair criticism in FB-0001 — the Book card currently shows a Name
and nothing else. **Say so if a different slice was meant.**

## What must be true

The card must show five things instead of one. Restated as behaviour:

1. The card shows the Book's **Book ID**. *(criterion 1)*
2. The card shows the **Name**. *(2 — already true today)*
3. The card shows the **Author**. *(3)*
4. The card shows the **Language**. *(4)*
5. The card shows the **Price**. *(5)*
6. A Book added through the form, where the person entered no Book ID, still
   shows one. *(6)*
7. A Language that is not from any predefined list is shown **unchanged**. *(7)*
8. A Price stored as 350 shows with **exactly two decimal places** — `350.00`,
   not `350` and not `350.0`. *(8)*
9. The Price is shown **in BDT**, and **no other currency appears on any card**.
   *(9)*

Criterion 9 has two halves and the second is the awkward one: it is a statement
about the whole page, not about one card.

## Approach

One file does the work: `src/web/render-book-card.js` grows from a Name and a
Delete control to a definition list of five fields plus the Delete control.

`renderBookCard(book)` already receives the whole Book from the store —
`{id, name, author, language, price}` — so **no store change, no route change,
no server change**. The store already returns `price` as a string with two
decimal places (`toPrice` in `library-store.js` formats poisha back to
`"350.00"`), so criterion 8 is satisfied by rendering that value as-is rather
than by formatting in the view. Two places formatting money is how they drift.

Every field goes through `escapeHtml`, as ADR-0002 requires. Three of the five —
Name, Author, Language — are typed by a person.

**Markup shape.** A `<dl>` of labelled pairs rather than bare text, so a field is
identifiable in a test by its label rather than by position, and so the card
degrades sensibly when a value is long:

```
<li class="book-card">
  <h2 class="book-card__name">…</h2>
  <dl class="book-card__fields">
    <dt>Book ID</dt><dd class="book-card__id">…</dd>
    <dt>Author</dt><dd class="book-card__author">…</dd>
    <dt>Language</dt><dd class="book-card__language">…</dd>
    <dt>Price</dt><dd class="book-card__price">BDT …</dd>
  </dl>
  <a class="book-card__delete" href="/?delete=…">Delete</a>
</li>
```

Name keeps its `<h2>` — it is the card's heading, not a field among equals.

## Test skeleton

9 tests minimum, one per criterion, each pinned `@covers REQ-BOOK-002@v1`.
Every test uses `aRunningLibrary` — see
`constraints/windows-locks-open-sqlite-files.md`.

```js
// tests/server/book-card.test.js

// @covers REQ-BOOK-002@v1
test('a Book card shows the Book ID', ...)
//   add a Book, read its issued id from the store, assert it appears in that
//   card — not merely somewhere on the page, since the id is also in the
//   Delete link's href and would match trivially

// @covers REQ-BOOK-002@v1
test('a Book card shows the Name', ...)
// @covers REQ-BOOK-002@v1
test('a Book card shows the Author', ...)
// @covers REQ-BOOK-002@v1
test('a Book card shows the Language', ...)
// @covers REQ-BOOK-002@v1
test('a Book card shows the Price', ...)

// @covers REQ-BOOK-002@v1
test('a Book added with no Book ID entered still shows one on its card', ...)
//   submits through POST /books, which has no Book ID control at all

// @covers REQ-BOOK-002@v1
test('a Language not drawn from any predefined list is shown unchanged', ...)
//   "Chakma" — present exactly, not normalised, not mapped, not dropped

// @covers REQ-BOOK-002@v1
test('a Price of 350 is shown with exactly two decimal places', ...)
//   asserts "350.00" AND that the card does not show a bare "350" or "350.0"

// @covers REQ-BOOK-002@v1
test('the Price is shown in BDT and no other currency appears on any card', ...)
//   three Books; assert BDT present on each card, and that no other currency
//   marker appears anywhere in the page

// No @covers — a rule, not a criterion:
test('a Book whose Author contains a script tag is shown as text', ...)
//   Author and Language become person-supplied output for the first time here
```

Each test reads **one card**, not the whole page. Asserting page-wide is how a
card test passes on another card's content.

## Decisions this forces

**1. Where the BDT marker goes, and in what form.** `৳350.00`, `BDT 350.00`, or
`350.00 BDT`. All three satisfy criterion 9. I propose **`BDT 350.00`** — ASCII,
unambiguous, and it cannot be confused with any other currency's symbol. This is
cheap now and tedious once nine tests assert a string. **This is the question I
raised in the earlier REQ-BOOK-002 plan and it was never answered.**

**2. Whether the Book ID is visible text or a `data-` attribute.** Criterion 1
says the card *shows* the Book ID, which reads as visible. I propose visible.
Worth confirming, because a visible integer id on every card is unusual in a
real product and the client asked for it explicitly — it may be that they meant
something more like a catalogue reference. **Also raised before and never
answered.**

Neither needs an ADR. Both need one word from you.

**3. Not an ADR, but state it:** criterion 8 is satisfied by the store's
existing formatting, not by new view logic. If a reviewer expects the view to
format money, they will look for code that is deliberately not there.

## What I am unsure about

- **Criterion 9's second half — "no other currency appears on any card" — is an
  assertion about absence across the whole page.** A test can check that no
  other currency marker appears in the rendered HTML, but "no other currency"
  is open-ended: I will check a fixed set (`$`, `€`, `£`, `¥`, `USD`, `EUR`,
  `GBP`, `INR`). That is a proxy, not a proof, and the test will say so.
- **The card grows from one line to six.** REQ-BOOK-014's criterion that every
  field is visible without clipping was written when the card had one field. It
  is `agreed` with no tests, and this slice is what will actually exercise it —
  I would expect to look at the rendered page after building, not just the HTML.
- **`renderBookCard` now has three responsibilities** — heading, fields, delete
  control — in one template literal. Still small, but this is the slice where
  splitting it would be reasonable if you would rather.
- **ADR-0003's absence**, above. Not blocking, but it should not stay lost.
